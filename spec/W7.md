# Wave 7: compile real software (Lua 5.4.7)

Read CONTRACT.md first. W1-W5 stay in scope (their hidden tests are run again, as regressions). W7 adds no new
language to the list in W5.md: it asks your compiler to build a real program, the Lua 5.4.7 interpreter, from its
unmodified sources, and scores what that interpreter does.

## What you are given

| Path | What |
|---|---|
| `spec/w7/lua/` | Lua 5.4.7's sources, unmodified (github.com/lua/lua, tag v5.4.7): the 33 `.c` files Lua's interpreter is made of and every header of its tree |
| `spec/w7/include/` | **the W7 header set** (below): the 8 provided headers of W1-W6, extended, and 13 more |
| `spec/w7/build.json` | the build, exactly: the source list, the defines, the include directories, the link line |
| `spec/w7/bench/` | the 6 runtime programs (Lua scripts) with their expected outputs |
| `visible/W7/` | 6 of the 28 scored test files of Lua's own test suite, the driver `w7test.lua`, its helpers, `README.md` (how to build Lua and run one), `manifest.json` |

## The build (the same for every compiler that is scored or compared)

```
clj-run -m ccc.main -I spec/w7/include -I spec/w7/lua -D LUA_COMPAT_5_3 -D LUA_USE_POSIX --batch <list>   (the 33 sources)
gcc <the 33 .s files> -o lua -lm
```

- **New in the driver: `-D NAME` and `-D NAME=VALUE`** (as cc's: `NAME` alone defines it as `1`), in single-file and
  batch mode, anywhere before the input, any number of times, beside `-I`. W1-W6's tests never pass `-D`.
- `LUA_USE_POSIX` is Lua's `LUA_USE_LINUX` without `LUA_USE_DLOPEN` (no C modules, so no `dlfcn.h`) and without
  readline: `_setjmp`/`_longjmp` for Lua's errors, `popen`, `mkstemp`, `fseeko`, `getc_unlocked`, `sigaction`,
  `gmtime_r`/`localtime_r`, `isatty`. `LUA_COMPAT_5_3` is what Lua's own makefile sets.
- The include path is `spec/w7/include`, then `spec/w7/lua`, and nothing else (CONTRACT.md section 1). Lua includes
  its own headers with `#include "x.h"`: search the including file's directory first, then the `-I` directories.
- The link adds `-lm` (libm) to the contract's `gcc out.s -o prog`.
- Every Lua source must compile: the interpreter is one program, and if any file fails or the link fails, every W7
  test and benchmark fails. Lua's sources use `__GNUC__` branches (jump tables through computed goto, `__builtin_expect`,
  attributes): since your compiler does not define `__GNUC__`, it takes the portable ones.

## The W7 header set (the decision)

**A curated set, not the system's glibc headers, and the same for both arms.** `spec/w7/include/` declares exactly
what Lua's 33 sources and this build need from libc, with glibc's x86-64 types and layouts, and nothing that needs a
GNU extension:

| | |
|---|---|
| extended | `stdio.h` (`FILE`, `stdin`/`stdout`/`stderr`, files, `popen`, …), `stdlib.h` (`getenv`, `strtod`, `mkstemp`, …), `string.h` (`strcoll`, `strspn`, `strpbrk`, `strerror`, …), `stddef.h` (`NULL` is `((void *)0)` here), `limits.h`, `stdint.h` |
| new | `assert.h`, `ctype.h`, `errno.h` (`errno` is `(*__errno_location())`), `float.h`, `locale.h` (glibc's `struct lconv`), `math.h` (`HUGE_VAL` is `(1e300 * 1e300)`), `setjmp.h` (glibc's 200-byte `jmp_buf`), `signal.h` (glibc's `struct sigaction`), `time.h` (glibc's `struct tm`), `unistd.h`, `sys/types.h`, `sys/wait.h` |

Why not the system's headers: glibc's headers are written for gcc. They lean on `sys/cdefs.h`, `__attribute__`,
`__asm__` symbol renames, `__extension__`, `__builtin_va_list`, `_Float128`, `__has_include`, `#include_next` and the
compiler's own `stddef.h`/`stdarg.h`/`float.h`, which glibc does not ship. Parsing them is a large preprocessor and
GNU-C project of its own that measures nothing about Lua, and it would make the score depend on the host's glibc
version. The curated set keeps CONTRACT.md's rule (the provided headers through `-I`, nothing else) and makes W7
about compiling a real program: its size, its idioms (`setjmp`/`longjmp`, unions, function pointers in tables, large
`switch`es, bit tricks, `va_list` passed on, `double` and `long long` everywhere), and its correctness. gcc -O0 builds
Lua with exactly this set (`-nostdinc`) and passes every scored test with it. W1-W6's tests keep `spec/include/`.

## What is scored (the hidden runner, `--wave=W7`)

1. **Regressions:** the hidden W1-W5 tests, as at W5 (the same category lines).
2. **Lua's test suite (correctness):** 28 files of Lua 5.4.7's own suite (`testes/`), each run by the driver
   (`lua w7test.lua full <file>`: all.lua's Linux defaults, `_soft` and `_port` false, the file loaded as all.lua's
   dofile loads it) in a fresh copy of the suite's directory, empty stdin, a limit of max(30 s, 20 × gcc -O0's time).
   A file passes on exit 0 and the line `W7-TEST-OK <file>`. A file is one test; the hidden ones are 22.
   - The 28 are every file all.lua runs that gcc -O0's Lua passes three times in a row in this mode, but `main.lua`
     (it needs C modules through `dlopen`, which this build leaves out, and `lua` on PATH).
   - Categories: `W7 language` (constructs, locals, goto, calls, closures, varargs, metamethods, the code generator,
     literals, very big programs), `W7 libraries` (strings, patterns, pack/unpack, utf8, tables, sorting, math,
     bitwise), `W7 runtime` (the collectors, coroutines, the C stack, errors, the debug library, the API), `W7 io-os`
     (files, the os library, require). Visible: 3 `language`, 3 `libraries`.
   - Before the tests, the runner checks the interpreter: it must print a fixed line and must fail an
     `assert(1 == 2)`. If it does not, every W7 test counts as failed (`W7 build: …; sanity fails`).
3. **Runtime:** the 6 programs of `spec/w7/bench/` (fib, nbody, spectral, bintrees, fannkuch, strops) run by your
   Lua and by gcc -O0's Lua (built from the same sources and headers), alternately, 5 times each, one at a time,
   medians; ratio = yours / gcc -O0's; a program that fails or runs over max(20 s, 20 × gcc -O0's time) counts 20.
   **W7 runtime score** = the geometric mean of the 6 ratios (lower is better). The runner times **variants** of these
   programs (other constants), not these files. gcc -O2's Lua and chibicc's Lua are timed beside them as references.
4. **Compile time:** the wall time of your compiler's batch over the 33 sources (one JVM), and the largest process's
   peak RSS, beside gcc -O0's and chibicc's (each running one process per file, serially).

The hidden run prints only lines like these, and a JSON summary:

```
W7 language: 2 of 8 fail
W7 total: 5 of 22 fail
W7 build: 0 of 33 sources fail to compile; link ok
W7 bench fib: 2.31x gcc -O0
W7 runtime score: 2.105 (geometric mean …; gcc -O2's Lua: 0.452; chibicc's Lua: 1.873)
W7 compile: 41.2 s wall and 812 MB peak RSS for the 33 sources in 1 batch (gcc -O0: 3.9 s, 61 MB; chibicc: 1.2 s, 9 MB)
```

The headline W7 measure is the pass rate on the 22 hidden test files; the runtime score and the compile time are
reported beside it. The build line names counts, never files: you have every source, so you can find a failing one
yourself.

## Rounds and time

Three feedback rounds, as every wave (the hidden lines above, sent when anything fails). W7 has its own caps:
**180 minutes of active time and $80**, counted from W7's release, whatever W1-W6 used.

## Rules (CONTRACT.md section 4, unchanged)

Your compiler compiles the C itself; you never compile or preprocess C with gcc or anything else (not Lua, not a
test, not to get a reference): gcc only assembles and links your `.s`. No downloads. No special cases: do not
recognize Lua's sources (their names, text or hashes) and emit code that was not derived from them. Do not edit
`spec/` or `visible/`; the runner uses the orderer's copies anyway.
