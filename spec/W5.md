# Wave 5: the rest of common C

Read CONTRACT.md first. W1-W4 stay in scope (regressions). This is the largest wave: most of the gcc torture tests
first fit here.

## In scope

- **switch.** `switch`, `case`, `default`, fall-through, `break`, and nesting inside loops; case values are integer
  constant expressions.
- **goto.** `goto` and labels, forward and backward.
- **Casts.** Explicit casts between all the scalar types and pointers, `(void)` casts, and the conversions they
  imply.
- **Integer types:**
  - `unsigned`, `long`, `long long`, `short`, `signed char`, `unsigned char`, `_Bool`, in every combination;
  - integer promotions and the usual arithmetic conversions;
  - unsigned wraparound;
  - sign and zero extension;
  - literal suffixes `u`, `l`, `ul`, `ll`, `ull`, and literals too big for `int` that take the next type up.
- **Bitwise.** `& | ^ ~ << >>` and `&= |= ^= <<= >>=`; `>>` on signed values is arithmetic.
- **Function pointers.** Declare, assign, compare and call them; use them as parameters and in arrays and structs;
  pass them to `qsort`; call through `(*fp)(…)` and `fp(…)`.
- **Storage.** `static` locals and file-scope `static` variables and functions, and `extern` declarations.
- **Floating:**
  - `float` and `double`: arithmetic, comparisons, literals;
  - conversions to and from integers;
  - arguments and returns in SSE registers per the ABI, and variadic calls (`printf("%f")`, which promotes float to
    double, with `%al` = the SSE count);
  - `va_arg(ap, double)`.
- **Misc:**
  - compound literals (`(struct P){1, 2}`) and bit-fields;
  - flexible array members;
  - `volatile`, `restrict` and `inline` (accepted; `inline` may be ignored);
  - `_Static_assert` and `__func__`.

- **Variable-length arrays (`W5 vla`).** Block-scope arrays whose size is computed at run time (`int a[n];`, also
  multi-dimensional and of structs), `sizeof` of them (evaluated at run time), VLA parameters (`void f(int n, int
  a[n][n])`, `int b[a++]`: the size expressions are evaluated on entry, in order), and the stack space they take being
  given back at the end of their block (a loop that declares one must not grow the stack).
- **GNU extensions (`W5 gnu`).** gcc's torture suite is written in GNU C; these are in scope:
  - statement expressions `({ …; e; })`, `typeof`/`__typeof__`, `__alignof__`, `__extension__`, and the `__inline__`,
    `__const__`, `__volatile__`, `__signed__`, `__restrict__` spellings;
  - `__attribute__((…))` on declarations: `aligned(n)` and `packed` change a layout (gcc's rules); `unused`, `used`,
    `noinline`, `noclone`, `noipa`, `always_inline`, `noreturn`, `const`, `pure`, `nothrow`, `cold`, `hot`, `format`,
    `nonnull`, `warn_unused_result`, `deprecated` and `malloc` are accepted and change nothing;
  - case ranges (`case 1 ... 5:`), labels as values and computed goto (`&&lab`, `goto *p;`), local labels
    (`__label__`), `?:` with the middle operand left out, zero-length arrays (`int a[0];`), empty initializer braces,
    binary constants (`0b101`), static initializers of flexible array members, arithmetic on `void *` (and
    `sizeof(void)` = 1), `__FUNCTION__`, `__PRETTY_FUNCTION__`,
    `__COUNTER__`, named variadic macros and `, ## __VA_ARGS__`;
  - these builtins: `__builtin_expect`, `__builtin_constant_p` (0 is a correct answer for anything not a constant),
    `__builtin_offsetof`, `__builtin_types_compatible_p`, `__builtin_choose_expr`, `__builtin_unreachable`,
    `__builtin_alloca`, `__builtin_prefetch` (does nothing), `__builtin_popcount`/`clz`/`ctz`/`ffs`/`parity` (and their `l`, `ll` forms),
    `__builtin_bswap16/32/64`, `__builtin_add/sub/mul_overflow` (and the typed `s`/`u` forms), `__builtin_inf`,
    `__builtin_inff`, `__builtin_huge_val`, `__builtin_huge_valf`, and `__builtin_X` for each libc function the
    provided headers declare (it is `X`).
  - Any other GNU extension is out (below), and no test uses one: the test builder runs `gcc -std=gnu11 -pedantic` on
    every test and drops any test with a pedantic warning this list does not name.

## Floats: the decision

**Floats are included**, as their own category (`W5 floating`). The reasons:

- They are part of everyday C, and the gcc torture suite uses them a lot.
- The SSE code generation and the float part of the SysV ABI are small and well documented.
- glibc's printf handles the formatting, so a compiler does not need its own float-to-text code.

Because they are a separate category, a compiler that skips them loses only that category's tests, and W6's
benchmarks use no floats. `long double` (x87), `_Complex` and decimal floats stay out.

## long double: the decision

**`long double` stays out** (the pilot asked). gcc's `long double` on x86-64 is the x87 80-bit format in 16 bytes,
passed in memory and computed on the x87 register stack: a second floating-point unit with its own code generation,
for a type few programs use. Including it would make W5's floating work mostly about x87 rather than common C. No
test uses `long double`, `_Complex` or `__float128`.

## Categories

`W5 floating`, `W5 gnu`, `W5 vla`, `W5 function-pointers`, `W5 goto`, `W5 switch`, `W5 misc`, `W5 storage`,
`W5 bitwise`, `W5 casts`, `W5 integer-types`. A test's category is the first of these it uses.

## Out of scope in every wave

- `long double`, `_Complex`, `__int128`, vector types, `_Generic`, `_Atomic`, `_Thread_local`, `_Alignas`;
- wide and Unicode string or character literals;
- `#pragma`, `#line`, `__FILE__`, `__DATE__`, `__TIME__`;
- nested functions, inline `asm`, and every GNU extension or builtin the `gnu` list above does not name.

No test uses any of these. K&R definitions are in scope from W1 (W1.md).
