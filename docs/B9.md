# Benchmark 9: make the compiler compile faster

You are given a working compiler for a subset of C, written in Clojure, that emits x86-64 GNU as (spec/CONTRACT.md).
It is correct: it passes its tests (spec/, visible/) and it builds the Lua 5.4.7 interpreter (spec/W7.md, spec/w7/),
whose own test suite passes. **The job is to make it compile faster without breaking anything.**

## How it is scored (lower is better)

The geometric mean of two ratios against the compiler as it is now, each the median of interleaved timings (yours and
the start's, one after the other):

1. the wall time of one batch (one JVM) over Lua's 33 sources, spec/W7.md's build exactly (about 11 s now);
2. the wall time of one batch over a held-out corpus of about a thousand small C test programs like those in visible/.

A candidate that breaks anything scores **1.0** (no credit):
- every hidden test the compiler passes now must still pass;
- Lua must build, pass its sanity check, and pass all of its hidden test files;
- the generated code's runtime score may not get more than 10% worse;
- the compile's peak memory may not grow more than 10%.

## Rules

- The compiler runs only as `clj-run -m ccc.main …` (the toolchain's fixed JVM flags; the classpath is the Clojure jars
  and ./src). So: **no native image, no JVM flags, no AOT compilation, no .class files or jars, no other launcher**;
  `src/` may hold only `.clj`, `.cljc` and `.edn` files.
- **Nothing survives from one compile to the next:** the judge runs your committed tree from a fresh read-only copy,
  with an empty HOME and TMPDIR.
- **No special cases:** do not recognise any input (Lua's file names, text or hashes, or a test's), and emit only code
  derived from the input. The held-out corpus is timed too, so speed that only helps Lua does not pay.
- As before: never compile or preprocess C with gcc, clang, cpp or anything else (gcc only assembles and links); no
  downloads and no network.

## The fast judge

`node <toolchain>/judge/judge.mjs fast --dir=<your tree>`, as often as you like (about 5 minutes): the visible tests of
waves 1-5, Lua's build and visible test files, then both timings against the start on the *visible* corpus. Timings
on this machine are noisy (about ±15%) because other work runs on it. Only the orderer's full judge, on your
committed tree, counts.
